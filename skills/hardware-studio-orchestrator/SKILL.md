# 总工程师工作流

## 输入与输出

输入：产品目标、已有工程、预算、约束和人工反馈。输出：阶段计划、依赖、工具交付、验收结果和下一步。

## 流程与调用

1. 读取工程 `AGENTS.md`（如有）与实际 MCP `tools/list`，区分已实现工具和未来能力。路线为 P0 CAD → P1 电子和固件 → P2 装配制造与测试反馈 → P3 持久化编排 → P4 完整参考产品与 UI。
2. 产品定义使用 `autonomous-hardware-product`。四柱托架建模使用 `parametric-cad-design`，调用 Schema → `cad_assess_parameters` → 建模 → 回读。正式尺寸缺少逐项证据时不能标为实际适配。
3. 电路与固件、制造准备、物理反馈分别加载本目录相邻的专业 Skill。P1/P2 MCP 未实现时输出缺口和可开展的文档工作，不生成虚构的工具结果。
4. 依据真实日志、报告和文件哈希验收阶段。P0 只有 CAD 模板可运行，不描述为完整多 Agent 或自动编排平台。
5. 记录完成项、失败原因、依赖与未验证项目；与下一阶段交接时携带源数据和构建 ID。

## 错误与验收

依赖或工具缺失时明确阻塞的工程环节；允许继续不依赖它的数字工作。构建失败不推进对应验收，禁止用手写“通过”替代工具。
每项完成声明都应可追溯到实际输出；烧录、上电、电机动作与下单必须等待明确人工确认。
